# WotbMod portal

Сайт-каталог модов World of Tanks Blitz: публикация версий, каталог с
поиском, страница мода с правами, зависимостями, совместимостью и хешем,
установка в игру одной кнопкой через установщик WotbMod. Бекенд — один
Python-файл без сторонних библиотек (`http.server` + `sqlite3`), фронтенд —
серверные шаблоны с одним CSS и одним JS без сборки. Папка самодостаточна:
её можно скопировать на хостинг целиком.

```text
wotbmod-portal/
  run.cmd, run.sh         запуск на ноуте: ключ, база, администратор, браузер
  config.example.json     настройки; копируется в config.json при первом запуске
  seed_demo.py            наполнить пустой портал примерами из SDK
  backend/portal_server.py  сервер: страницы, JSON API, проверка пакетов
  backend/vendor/         копии модулей SDK (wotbmod*.py), tools/sync_sdk.py
  frontend/templates/     HTML-шаблоны страниц
  frontend/static/        app.css, app.js, logo.svg
  tools/portal_keygen.py  ключ подписи портала
  deploy/                 Caddyfile (HTTPS), systemd unit, Dockerfile, compose, backup.sh
  tests/test_portal.py    сквозной тест: регистрация → публикация → установка
  data/                   создаётся при запуске: portal.sqlite3, artifacts/, outbox/, portal.key
```

## Проверить на ноутбуке

1. Нужен Python 3.11 или новее (`python --version`).
2. В этой папке: `run.cmd seed` (Windows) или `./run.sh seed` (Linux/macOS).
   Первый запуск создаст `config.json`, папку `data`, ключ подписи
   `data/portal.key`, администратора из `config.json`
   (`admin@example.org` / `change-me-before-hosting`) и наполнит каталог
   примерами из соседней папки `mod_api` (демо-разработчик
   `demo@example.org` / `demo-demo-demo`). Без `seed` каталог будет пустым.
3. Откроется `http://127.0.0.1:8080`. Что посмотреть:
   - каталог: поиск, фильтры, сортировка — обновляются без перезагрузки;
   - страница мода: хеш с кнопкой копирования, права с метками риска,
     проверка кода, версии, оценка, отзывы;
   - «Установить в игру» → страница установки → кнопка `wotbmod://…`.
     Чтобы она сработала, на этом же компьютере один раз выполните из SDK
     `python tools\wotbmod_launcher.py register --game-root "<папка игры>"`;
     иначе страница покажет ручной путь;
   - кабинет (войдите как demo): загрузка версии, токены;
   - модерация (войдите как admin): заявки, жалобы, «проверен», снятие мода;
   - `/compat`, `/docs`, `/api/v1/index.json`.
4. Письма (подтверждение почты, сброс пароля) без SMTP лежат в `data/outbox/`.

Остановить — Ctrl+C. Данные остаются в `data/`; удалить папку — начать с нуля.

## Залить на хостинг

Нужен любой хост с Python 3.11+ (VPS) или Docker. Что сделать один раз:

1. Скопировать папку целиком (без `data/` с ноута, если не хотите переносить
   демо-данные). `backend/vendor/` уже содержит нужные модули SDK
   (`python tools/sync_sdk.py --check` подтверждает, что они актуальны).
2. `cp config.example.json config.json` и поправить:
   - `base_url` — публичный адрес с https, например `https://mods.example.org`
     (он попадает в ссылки `wotbmod://…?source=` и в письма);
   - `admin_email` и `admin_password` — свои (аккаунт создаётся при старте,
     потом строки можно очистить);
   - `smtp` — `host:port` почтового релея, если письма нужны по-настоящему;
   - `smtp_user`, `smtp_password`, `mail_from` — логин, пароль и адрес отправителя
     для релея с авторизацией (Resend: `smtp.resend.com:587`, логин `resend`,
     пароль — API-ключ, отправитель `noreply@<ваш домен>`);
   - `host` — `127.0.0.1` за reverse proxy или `0.0.0.0` в Docker.
3. Ключ подписи: `python3 tools/portal_keygen.py --out data/portal.key --key-id blitzforge-portal-2026`.
   Публичный `data/blitzforge-portal-2026.p256` раздайте игрокам в
   `<игра>/mods/trust/keys/` — тогда релизы проверенных разработчиков будут
   считаться доверенными и loader-ом, и CLI.
4. HTTPS: `deploy/Caddyfile` (поменять домен) — Caddy сам получит
   сертификат; или свой nginx с `proxy_pass http://127.0.0.1:8080` и
   `client_max_body_size 300m`.
5. Автозапуск: `deploy/wotbmod-portal.service` (пути `/opt/wotbmod-portal`,
   пользователь `wotbmod`) или `docker compose -f deploy/docker-compose.yml up -d`.
6. Резервные копии: `deploy/backup.sh <папка портала> <куда>` — база через
   онлайн-backup SQLite, артефакты, ключ.

Проверка после запуска: `curl https://mods.example.org/api/v1/index.json`
отдаёт `{"schema": 1, ...}`; на странице любого мода кнопка установки ведёт
на `wotbmod://install/<id>@<версия>?source=https://mods.example.org/api/v1`.

## Как это работает

- **Пакет** (`.wotbmod`) загружается в кабинете или командой
  `wotbmod publish --to https://<адрес>/api/v1 --token …`. Портал проверяет
  его как loader в игре (структура, хеш, подпись), прогоняет статический
  сканер, и версия становится неизменяемой.
- **Роли**: пользователь → разработчик (по заявке, одобряет модератор) →
  проверенный разработчик (его релизы подписывает ключ портала) →
  модератор → администратор. Отметку «проверен» ставит только модератор.
- **Установка**: страница `/install/<id>@<версия>` открывает
  `wotbmod://install/…`; установщик на компьютере игрока скачивает релиз,
  сверяет хеш и подпись, показывает права и зависимости и ставит зависимости
  первыми. Без установщика — ручной путь через CLI.
- **JSON API** под `/api/v1` (каталог `index.json`, моды, релизы, артефакты,
  публикация, оценки, отзывы, жалобы, совместимость, крэши, модерация,
  audit) и старая форма `/api/mods` для каталога в ангаре. Полный список
  маршрутов — в `backend/portal_server.py`, функция `_routes()`.

## Дизайн

Одна нейтральная шкала (холодный графит), один акцент (кобальт) только там,
где действие что-то меняет или подтверждает: «Установить», «Опубликовать»,
отметка «проверен». Один радиус 8 px на всём, глубина только линиями и
воздухом: без теней, размытия и градиентов. Один шрифт Onest, моноширинный
JetBrains Mono только для id и хешей; оба захощены в `frontend/static/fonts`
(кириллица и латиница), к Google Fonts сайт не ходит. Тёмная тема по
умолчанию, светлая включается по `prefers-color-scheme: light`. Каталог
показан строками, а не карточками; права сгруппированы по уровню, а не
рассыпаны по бейджам. Анимация одна: короткое появление страницы, плюс ответы
на действия; `prefers-reduced-motion` выключает всё. Без JavaScript всё
работает, с ним: живой поиск, копирование хеша, статус передачи установщику,
оценка одним кликом, загрузка версии без перезагрузки.

## Тесты

`python tests/test_portal.py` — поднимает портал на `127.0.0.1:0` и проходит
весь путь: регистрация, письмо, заявка, токен, `wotbmod release` +
`publish`, страницы, скачивание, отказ заменить версию, оценка/отзыв/жалоба,
проверка модератором и подпись портала, установка через CLI из портала,
старая форма `/api/mods`, сброс пароля, роли, сканер, audit, крэши, takedown.
Из SDK его запускает `mod_api\tests\build_wotbmod_cli_tests.cmd`.
