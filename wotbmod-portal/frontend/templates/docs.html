Как это работает

Мод: папка с manifest.json. Пакет: тот же мод одним файлом .wotbmod. Релиз: пакет с подписью и записью о его хеше. Каталог: список релизов, который читает и этот сайт, и установщик на вашем компьютере.

Установка

  1. Один раз поставьте набор BlitzForge: он кладёт в игру загрузчик, инструменты и регистрирует установщик для кнопки ниже.
  2. На странице мода нажмите «Установить в игру». Браузер откроет ссылку wotbmod://install/<id>@<версия>, установщик покажет права, зависимости и хеш и спросит подтверждение.
  3. Из терминала: wotbmod install <id> --catalog {{base_url}}/api/v1 (команда появляется после установки набора). Без каталога: скачайте .wotbmod и .sig и передайте файл той же команде.

Полный справочник Lua API — все функции, фасады, примеры и формат пакетов — в документации BlitzForge.

Публикация

  1. Соберите релиз: wotbmod release <папка> --sign-with-key <ключ> --key-id <id>. Команда сама прогонит статическую проверку.
  2. Загрузите его в кабинете или командой wotbmod publish --to {{base_url}}/api/v1 --token ….
  3. Заявите совместимость с build-ом клиента на странице мода. Версия после публикации неизменяема.

Первый мод за 15 минут

Папка с manifest.json и main.lua, проверка в игре без сборки (папка mods\lua, горячая перезагрузка), ключ, релиз, публикация — по шагам в руководстве «Первый мод за 15 минут». Там же — известные ограничения текущего клиента: что нельзя сделать со штатным UI и как это обходят примеры.

Отзыв релизов и сбои

Снятый автором или модератором релиз попадает в список revoked каталога. Команда wotbmod sync убирает такие релизы с компьютера; кнопка «Установить в игру» запускает её после каждой установки. Если загрузчик дважды подряд отключил мод из-за падения клиента, та же команда сообщает об этом порталу: мод, версия, сборка клиента и счётчик, без личных данных. Отключается строкой [telemetry] crashes=0 в mods\mods.ini.

Правила модерации

Мод просит только те права, которые использует; возвращает клиент в исходное состояние при выключении; не трогает сеть без network.http.allowlisted; не меняет то, что видит противник, и не играет за игрока. Права уровня REVIEWED модератор читает в коде целиком, UNSAFE в каталог не публикуется. О каждом решении — отметке, снятии, скрытии — разработчику приходит письмо, а строка остаётся в аудите мода. Полный текст: правила модерации.

Роли

  • Пользователь оценивает, комментирует, жалуется и может подать заявку разработчика.
  • Разработчик публикует свои моды и заявляет совместимость.
  • Проверенный разработчик прошёл проверку модератора: его моды получают отметку, а релизы подписывает портал, чтобы игроку хватало одного доверенного ключа.
  • Модератор разбирает заявки и жалобы, ставит отметку «проверен», снимает моды. Администратор назначает роли.

Отметку «проверен» ставит только модератор; сам разработчик не может поставить её себе.

Безопасность

  • Пакет проверяется дважды одинаковыми правилами: здесь при загрузке и loader-ом в игре. Хеш, подпись ECDSA P-256, структура архива.
  • Статическая проверка ищет в нативном коде инъекцию в чужие процессы, системные хуки, сетевые вызовы без объявленного права; в Lua: вызовы, которых в host-е нет.
  • Права показаны до установки с меткой риска. При обновлении установщик называет новые права словами «эскалация прав».
  • Моды не получают сырого сетевого канала, скрытых данных противника и не меняют то, что решает сервер.

API

Каталог: GET /api/v1/index.json, GET /api/v1/mods, GET /api/v1/mods/<id>, артефакты по /api/v1/releases/<id>/<версия>/artifact и …/artifact.sig. Публикация: POST /api/v1/releases с токеном. Старая форма для каталога в ангаре: GET /api/mods. Полный список есть в README портала.
