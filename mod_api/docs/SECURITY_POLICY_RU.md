# Политика безопасности BlitzForge

## Что платформа обещает игроку

- **Ничего не ставится молча.** Установщик (`wotbmod install`, кнопка
  `wotbmod://` в браузере, кабинет портала) показывает SHA-256, права по
  tier с человеческой подписью риска, зависимости и результат сканера — и
  ждёт подтверждения. Обновление называет новые права словами
  `PERMISSION ESCALATION` до вопроса «ставить?».
- **Подпись проверяется дважды** — CLI и loader-ом в игре, одинаковыми
  правилами (ECDSA P-256/SHA-256, trust store `mods/trust/keys`, подписанный
  список отзывов). `[policy] require_trusted_signature=1` в `mods.ini`
  делает подпись обязательной: неподписанные и неизвестные пакеты не доходят
  до `LoadLibrary`.
- **Версия неизменяема.** Опубликованные байты нельзя подменить ни
  разработчику, ни модератору; можно только снять релиз.
- **Крэш-луп не ломает игру.** Loader сам отключает мод, дважды подряд
  уронивший клиент (`mods/cache/auto_disabled_mod.ini`); `wotbmod
  quarantine` объясняет и снимает карантин, `wotbmod rollback` возвращает
  прошлую версию без ручного копирования DLL.
- **Откат всегда есть.** Каждая замена оставляет копию в
  `mods/cache/install_backups/`.

## Чего моды не делают — и API не позволяет

- **Нет сырого сетевого канала.** Ни отправки, ни подмены, ни задержки, ни
  повтора сообщений сервера (`bigworld.rpc.*` остаётся вне API; интерфейсы
  с таким именем не публикуются).
- **Нет скрытых данных противника.** Видимы только те машины, что клиент и
  так рисует (`entity.public.visible`); ни позиций за пределами видимости,
  ни HP скрытых целей, ни направления невидимого противника.
- **Нет серверных мутаций.** Урон, попадания, перезарядка, экономика — то,
  что решает сервер, мод не меняет; `gameplay.tweak.*` меняет только то, что
  этот клиент показывает.
- **Нет установщиков внутри пакета.** Скрипты и исполняемые файлы кроме
  entrypoint-DLL — блокирующая находка сканера.

Нативный код может попытаться обойти это. Поэтому нативный пакет получает
права по tier, `UNSAFE`-tier виден игроку красной меткой, «проверен» ставится
только после воспроизводимой сборки из исходников (`REVIEW_POLICY_RU.md`), а
подпись такого автора отзывается навсегда при первом подтверждённом обходе.

## Lua

Lua-моды исполняются в host-е без `os`, `io`, `package.loadlib`, `debug` и
FFI; каждый вызов `wotb.*` проверяется по правам manifest. Сканер отмечает
попытки использовать то, чего в host-е нет, и модули без прав. Lua-мод не
может загрузить нативный код.

## Как сообщить об уязвимости

Опишите проблему в жалобе на странице мода (кнопка «Пожаловаться») или,
если она касается платформы (loader, CLI, портал), — в закрытой заявке
разработчика администратору портала. Не публикуйте эксплойт до исправления.
Исправление платформы выходит новой версией loader-а и CLI; затронутые
релизы снимаются, ключи — отзываются через `revocations.list`.

## Что записывается

Портал хранит audit-журнал: кто загрузил, опубликовал, снял, проверил,
назначил роль — с временем. Loader пишет `wotb_mod_loader.log` (что
загружено, что заблокировано и почему), `mods/cache/crash_history.ini` и
`auto_disabled_mod.ini`. `wotbmod info <id>` собирает всё это в одном месте.
