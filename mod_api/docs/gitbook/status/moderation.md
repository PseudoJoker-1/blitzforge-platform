# Правила модерации BlitzForge

Что модератор проверяет, что портал делает сам, и что бывает с модом,
который правила нарушил. Правила короткие, потому что большую часть
проверяет код: права объявлены в манифесте, статический сканер сверяет их
с вызовами, подпись фиксирует байты.

## Кто и что решает

| Роль | Может |
| --- | --- |
| Пользователь | ставить оценки, писать и править свои отзывы, жаловаться |
| Разработчик | публиковать моды, заявлять совместимость, снимать свои релизы, скрывать свой мод |
| Проверенный разработчик | то же; его релизы подписывает портал |
| Модератор | заявки, жалобы, отметка «проверен», скрытие отзывов, снятие релизов и модов |
| Администратор | роли, удаление неподтверждённых аккаунтов, объявление на сайте |

Отметку «проверен» разработчик не может поставить себе. Модератор не
может снять роль с администратора.

## Уровни прав и что они значат для проверки

- **SAFE** — чтение состояния, свои панели, свои звуки, storage. Мод только
  с SAFE-правами проверяется по описанию и скану; код читается выборочно.
- **REVIEWED** — правки штатного UI, HUD, камера в бою, смена кластера,
  подмена звуков клиента, GES publish, управление пакетами из игры
  (`packages.manage`: мод запускает `wotbmod.exe`). Модератор читает код
  целиком: что именно мод меняет и возвращает ли обратно в `on_disable`.
- **UNSAFE** — сырые хуки, произвольные ресурсы игры. Такие моды не
  публикуются в каталоге; только по договорённости с командой и с
  отдельной страницей рисков.

## Что мод обязан

1. Просить только те права, которые использует. Сканер отклонит релиз,
   где вызовы шире манифеста; модератор отклонит заявку, где манифест
   шире вызовов без объяснения.
2. Возвращать клиент в исходное состояние в `on_disable`: спрятанные
   контролы показать, панели снять, подписки отписать.
3. Не трогать сеть, кроме `network.http.allowlisted`, и не отправлять
   ничего, что идентифицирует игрока, без явного согласия в описании.
4. Не изменять то, что видит противник, и не автоматизировать игру
   (автоприцел, автозапуск снаряжения). Такие моды снимаются без
   предупреждения.
5. Иметь описание на русском или английском: что делает, на каком клиенте
   проверен, как выключить.

## Что делает портал сам

- Подписывает релизы проверенных разработчиков своим ключом.
- Ведёт аудит: каждая отметка, снятие, роль — строка в журнале, видна
  автору на странице мода.
- Пишет разработчику на почту при одобрении и отклонении заявки, при
  отметке «проверен» и её снятии, при скрытии мода и снятии релиза.
- Ограничивает: 10 новых релизов в час на разработчика, 3 регистрации в час
  с адреса, аккаунты без подтверждённой почты удаляются через 3 дня.
- Снятые релизы и снятые моды попадают в `revoked` каталога; `wotbmod sync`
  (его запускает кнопка «Установить в игру» после каждой установки) убирает
  их у игроков.

## Жалобы

Жалоба открывается на мод, релиз или отзыв. Модератор либо разбирает
(«resolved» — с действием: скрыть отзыв, снять релиз, снять мод), либо
отклоняет («dismissed»). Автор видит результат в аудите мода. Повторная
жалоба на то же без новых фактов отклоняется.

## Снятие мода

Снятие — одно действие модератора: мод скрыт из каталога, все его релизы
отозваны, открытые жалобы закрыты, автору уходит письмо с причиной. Автор
может ответить на письмо; возврат мода в каталог — действие модератора
«Вернуть». Установленные копии у игроков уходят при следующем `wotbmod sync`.

## Крэши

Загрузчик сам отключает мод, который два раза подряд уронил клиент, и
`wotbmod sync` сообщает об этом порталу (мод, версия, сборка клиента,
счётчик — без личных данных; отключается строкой `[telemetry] crashes=0`
в `mods.ini`). Три таких сообщения от разных игроков на один релиз —
повод модератору снять релиз до ответа автора.
