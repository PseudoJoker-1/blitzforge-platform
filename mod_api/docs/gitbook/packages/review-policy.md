# Политика проверки нативных пакетов

«Проверен» — это утверждение модератора о конкретном разработчике и его
пакетах, не автоматический статус. Ниже — что модератор обязан сделать до
того, как поставить значок, и что снимает его.

## Словарь

- **Нативный пакет** — `.wotbmod` с `type: native`: внутри DLL, которая
  загружается в процесс игры и получает права по tier из manifest.
- **Tier** — уровень прав: `SAFE` (свои данные), `GAMEPLAY_TWEAK` (HUD,
  камера, вид техники на этом клиенте), `REVIEWED` (сеть, ресурсы игры,
  чужие контролы), `UNSAFE` (`native.*`, `render.native`, полный доступ к
  процессу).
- **Сканер** — `wotbmod scan`: импорты DLL, секции, строки, Lua-вызовы,
  соответствие правам. Портал прогоняет его при загрузке и хранит отчёт в
  release-записи (`scan`).

## Что делает модератор перед «проверен»

1. **Личность и история.** Заявка разработчика с описанием, подтверждённая
   почта, отсутствие открытых жалоб. Первый нативный мод нового автора не
   получает «проверен» раньше двух недель в каталоге без жалоб.
2. **Сканер чист.** В release-записи `scan.summary.block == 0`; каждое
   `warn` объяснено в changelog (например, `network:https://host` объясняет
   импорт WinHTTP; `native.hooks` объясняет `OpenProcess`).
3. **Права соответствуют функции.** Мод «прицел и миникарта» не просит
   `native.memory_patch`. Tier `UNSAFE` — только для модов, чью
   необходимость в этом модератор понимает и может назвать.
4. **Воспроизводимая сборка.** Для tier `REVIEWED` и выше автор даёт
   исходники и команду сборки; модератор собирает и упаковывает
   (`wotbmod pack` детерминирован) и сверяет SHA-256 с релизом. Не сошлось —
   не «проверен».
5. **Живой прогон.** Мод ставится через `wotbmod install --require-signature`
   на текущий build клиента, один бой, `wotbmod info <id>` без ошибок в
   логе loader-а, `wotbmod quarantine` пуст.
6. **Запись в audit.** Действие `mod.verify` попадает в журнал с id
   модератора; отзыв значка — `mod.unverify` с причиной в жалобе или отзыве.

## Что снимает значок или релиз

- любая блокирующая находка сканера в новой версии;
- эскалация прав без объяснения в changelog;
- жалоба, подтверждённая модератором (вредоносное поведение, обход API,
  скрытые данные противника, чужой код без указания источника);
- подпись отозванным ключом (`mods/trust/revocations.list`) — релизы такого
  ключа отклоняет и loader, и CLI;
- крэш-луп у заметной доли игроков (`wotbmod report-crash` присылает на
  портал сведения о карантине; страница `/compat` показывает их по версиям
  и build-ам клиента).

Снятие релиза (`unpublish`) — обратимо; отзыв ключа — нет: новый релиз
потребует нового ключа и новой проверки.

## Что модератор не делает

Не правит чужой пакет, не подписывает то, что не собрал сам, не ставит
«проверен» по просьбе без шагов 1–6, не удаляет жалобы без решения
(resolve/dismiss всегда остаются в журнале).
