# Установка из браузера: ссылки `wotbmod://` (этап 5)

Веб-страница не может писать в папку игры — и не должна. Она может лишь
открыть ссылку со схемой `wotbmod://`, которую Windows отдаёт программе,
установленной вами самими. Эта программа — `tools/wotbmod_launcher.py`. Она
читает ссылку, скачивает **каталог** (тот же `index.json`, что читает
`wotbmod install --catalog`), находит в нём ровно ту версию, что названа в
ссылке, сверяет SHA-256 скачанного файла с записью каталога и передаёт файл
установщику этапа 3 — тот проверяет пакет и подпись ещё раз, показывает хеш,
права и план зависимостей и спрашивает подтверждение до того, как что-то
попадёт в `mods/`.

## Контракт ссылки

```text
wotbmod://install/<id>@<версия>?source=<адрес каталога>
wotbmod://uninstall/<id>
```

`<id>` — идентификатор мода (`author.mod_name`), `<версия>` — точная
семантическая версия, `source` — базовый адрес каталога по http(s):
папка-каталог за статическим сервером (`https://host/catalog/`) или портал
(`https://host/api/v1`). Ничего другого ссылка нести не может: путь к DLL,
локальный путь, `file:`, лишние параметры и фрагменты отклоняются до любого
сетевого запроса (см. `parse_link` и тест `test_links_are_parsed_strictly`).
Страница установки на портале (`/install/<id>@<версия>`) формирует ровно
такую ссылку и рядом даёт ручной путь на случай, если launcher не установлен.

## Установка launcher-а

Игроку ничего делать не нужно: установщик `BlitzForge-Setup-<версия>.exe` (или
`install.ps1 -RegisterLauncher`) регистрирует схему сам через собранный
`wotbmod.exe`, в котором CLI и launcher живут в одном файле:

```bat
rem то, что делает установщик; вручную нужно только без него
"<папка игры>\wotbmod\wotbmod.exe" launcher register --game-root "<папка игры>"
"<папка игры>\wotbmod\wotbmod.exe" launcher status
"<папка игры>\wotbmod\wotbmod.exe" launcher unregister
```

Из исходников SDK то же самое делает `python tools\wotbmod_launcher.py register
--game-root "<папка игры>"`. `register` пишет `HKCU\Software\Classes\wotbmod`
с командой `"<wotbmod.exe>" launcher open "%1"` (для Python-варианта —
`"<python>" "<путь>\wotbmod_launcher.py" open "%1"`) и запоминает папку игры
в `%LOCALAPPDATA%\WotbMod\launcher.json`; журнал — `launcher.log` там же.
Переменная `WOTBMOD_LAUNCHER_HOME` переносит эту папку (так делают тесты).

## Что происходит по клику

1. `parse_link` — строгий разбор (выше).
2. `Catalog(source).versions(id)` — в каталоге ищется **ровно** названная
   версия; нет версии, статус не «published», или `client.builds` записи не
   содержит build этого клиента (`11.20.0.887`) — отказ.
3. `Catalog.fetch` — скачивание артефакта и его `.sig`; хеш файла обязан
   совпасть с `artifact.sha256` записи, иначе отказ.
4. `wotbmod install <файл> --catalog <source> --sidecar <sig>` — всё, что
   делает установщик этапа 3: отпечаток клиента, allowlist manifest, CRC,
   вердикт подписи (`--require-signature` или `[policy]` в `mods.ini`
   делают его обязательным), зависимости из каталога **раньше** зависимого,
   несовместимости, сводка с SHA-256 и правами, вопрос `[y/N]`, атомарная
   замена с резервной копией, ledger.
5. Повторный клик по той же ссылке находит тот же хеш установленным и
   заканчивается словами «already installed with the same hash» — ничего не
   перезаписывается (идемпотентность).
6. `uninstall/<id>` — `wotbmod uninstall`: удаляет файлы только этого id,
   отказывает, если пакет нужен другому установленному, копию сохраняет.

В конце launcher ждёт Enter (окно консоли открыл браузер); `--no-pause`,
`--yes` и `--game-root` нужны скриптам и тестам.

## Lua-пакеты

Lua-мод — папка с маленьким manifest (`id`, `name`, `version`, `entrypoint`,
`permissions`; схема `schemas/wotbmod-lua-manifest-v1.schema.json`), которую
Lua host загружает из `<игра>/mods/lua/<id>/`. Упакованный в `.wotbmod`
(`wotbmod release <папка>` понимает Lua-manifest сам — у него нет
`manifest_version`), он путешествует, подписывается и проверяется точно как
нативный пакет; отличие одно — куда его кладёт `install`: **распаковывает**
в `mods/lua/<id>/` (через staging-папку и атомарную замену), а не оставляет
архивом в `mods/`, где нативный loader отверг бы незнакомый manifest. Сам
архив и его `.sig` сохраняются в `mods/cache/lua_packages/`, чтобы
`wotbmod list` мог вынести вердикт о подписи; `update`, `rollback` и
`uninstall` работают через те же резервные копии. Content-only пакеты идут
нативным путём (`type: content` в manifest v1).

## Тесты

`tests/test_wotbmod_launcher.py`: строгий разбор ссылок; установка названной
версии с зависимостью раньше зависимого и идемпотентный повтор; отказ при
подменённом хеше в каталоге, отсутствующей версии, чужом build клиента и
недоверенной подписи под обязательной политикой; Lua-пакет — распаковка в
`mods/lua/<id>/`, кеш архива, `list` с вердиктом подписи, `update` и
`rollback`, `uninstall` по ссылке без следов на других модах; регистрация и
снятие схемы в HKCU под одноразовым именем (только Windows). Запуск —
`tests\build_wotbmod_cli_tests.cmd`.
