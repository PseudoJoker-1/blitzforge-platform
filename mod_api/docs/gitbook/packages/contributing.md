# Как отдать мод в каталог BlitzForge

Этот документ — для того, кто написал мод и хочет, чтобы его увидели и
поставили другие. Он про правила игры, не про API: API описан в
`QUICKSTART_RU.md`, `LUA_MODS_RU.md` и `WOTBMOD_PACKAGE_FORMAT_RU.md`.

## Три шага

1. **Соберите релиз.** `wotbmod release <папка> --sign-with-key <ключ> --key-id <id>`
   делает `.wotbmod`, подпись и `*.release.json`. Перед этим команда сама
   прогоняет статическую проверку (`wotbmod scan`): пакет с блокирующими
   находками не выпускается, пока вы их не уберёте или не примете сознательно
   (`--allow-scan-findings` — находки увидит каждый игрок на странице мода).
2. **Опубликуйте.** В кабинете портала или `wotbmod publish --to
   https://<портал>/api/v1 --token <токен>`. Версия неизменяема: те же байты
   можно отправить повторно, другие — только под новым номером.
3. **Заявите совместимость.** На странице мода (или `POST
   /api/v1/mods/<id>/compat`) отметьте, на каком build клиента вы проверяли:
   `works`, `broken` или `untested`. Игроки видят это до установки.

## Что обязательно

- **Права — по минимуму.** Manifest просит только те permissions, которые
  код действительно использует. `wotbmod scan` подсветит `wotb.<модуль>` без
  соответствующего права; портал подсветит эскалацию прав между версиями,
  а `wotbmod install` напишет игроку `PERMISSION ESCALATION` при обновлении.
- **Один id навсегда.** `author.mod_name` — с вашим префиксом; сменить id —
  значит выпустить другой мод.
- **Changelog в каждой версии** (`--notes` или поле в кабинете): что
  изменилось и зачем нужны новые права, если они появились.
- **Никаких сторонних установщиков.** Пакет содержит только манифест, код
  мода и ресурсы; скрипты (`.bat`, `.ps1`, `.exe`-установщики) — блокирующая
  находка сканера.
- **Только клиентские эффекты.** Мод не отправляет и не подменяет сетевые
  сообщения, не читает скрытые данные противника и не меняет то, что решает
  сервер (см. `SECURITY_POLICY_RU.md`). API этого и не даёт; попытка обойти
  его нативным кодом — причина для снятия мода и отзыва ключа.
- **Нативный код — с исходниками.** Для значка «проверен» модератор должен
  собрать тот же `.wotbmod` из исходников (детерминированная упаковка даёт
  тот же SHA-256); см. `REVIEW_POLICY_RU.md`.

## Что вы получаете

- страницу мода с хешем, правами, зависимостями, совместимостью,
  статистикой загрузок и обновлений, оценками и отзывами;
- ссылку `wotbmod://install/<id>@<версия>` для установки из браузера;
- после проверки — значок «проверен» и подпись портала на релизах, так что
  игроку достаточно доверять одному ключу;
- журнал действий (audit trail) по каждой публикации — кто, что и когда.

## Как устроена модерация

Модераторы отвечают на заявки разработчиков и жалобы, ставят и снимают
«проверен», снимают релизы с публикации. Решения видны в audit-журнале
(`GET /api/v1/mods/<id>/audit` для модераторов). Спор по решению — новая
заявка или отзыв с описанием; повторная жалоба без новых фактов
закрывается.

## Кодекс

Уважайте игроков и других авторов: без чужого кода без указания источника,
без вводящих в заблуждение описаний, без «читов» под видом HUD-модов.
Нарушение — снятие мода, повтор — блокировка аккаунта разработчика.
