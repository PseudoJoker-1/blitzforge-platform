# blitzforge.catalog.ui — экран каталога в ангаре (ресурсный пакет)

Штатная половина каталога модов. Пакет подменяет
`UI/Screens3/Lobby/Hangar/Hangar.yaml` и добавляет в него две вещи:

- `ModCatalogButton` — иконка в левой колонке ангара (тот же прототип
  `IconButtonWithBadge/IconButton`, что у турнирной и сюжетной кнопок);
- `ModCatalogScreen` — сам экран, скрытый: шапка с кнопкой «назад», заголовок,
  вкладки «КАТАЛОГ» и «КАСТОМНЫЕ МОДЫ», кнопка «ОБНОВИТЬ», восемь рамок
  карточек с «лицами» кнопок (УСТАНОВИТЬ / ОБНОВИТЬ / УДАЛИТЬ / ВЫКЛЮЧИТЬ /
  ВКЛЮЧИТЬ / СИСТЕМНЫЙ / НЕ ДЛЯ 11.20), пейджер, полоса «ПЕРЕЗАПУСТИТЬ
  КЛИЕНТ» и диалог подтверждения. Всё на классах стилей клиента
  (`Color.style.yaml`, `Font.style.yaml`, `SimpleButton.style.yaml`).

Все подписи — литералы: на 11.20 текст штатных контролов из мода не меняется.
Lua-мод `blitzforge.catalog` только показывает и прячет контролы (настоящий
`SetVisibilityFlag`), ловит отпускание указателя и сверяет его с
прямоугольниками кнопок, а имена, версии и статус рисует своими текстовыми
контролами игровым шрифтом поверх рамок. Ни биндингов, ни `.actions` в
пакете нет — файл действий ангара не трогается.

## Пересборка

```
python patch_dvpl.py extract UI/Screens3/Lobby/Hangar/Hangar.yaml   # из _mod_tools, чистый файл в work/
python mod_api/tools/build_catalog_ui.py work/Hangar.yaml --game-root "<игра>" [--version 1.0.1]
```

Генератор проверяет структуру YAML (отступы, повторы ключей) и что каждый
цветовой класс есть в `Color.style.yaml` клиента; в `manifest.json` пишет
`stock_sha256` исходного файла и `sha256` результата. После патча клиента:
извлечь новый `Hangar.yaml`, пересобрать, поднять версию.

Пакет ставится вместе с `blitzforge.catalog` мастером установки и
обновляется с портала как обычный ресурсный пакет.
