# Lua Reload Timer

Компактная боевая панель перезарядки и боекомплекта. Показывает остаток
перезарядки с точностью до десятой секунды, долю пройденного цикла, текущий
снаряд и запас по типам снарядов — и ровно там, где данных нет, честно пишет,
что их нет.

Панель стоит у правого края экрана, примерно на трети высоты: прицел в центре
она не перекрывает, списки команд сверху и нижнюю полосу интерфейса — тоже.

```text
+------------------------------------+
| ПЕРЕЗАРЯДКА                        |
| 6.0 с                              |
| [###.....]  37 %  ·  цикл 9.4 с    |
| СНАРЯД №2  ·  запас —              |
| запас снарядов клиент не публикует |
| интерполяция  ·  событие 3 с назад |
+------------------------------------+
```

## Что показывает каждая строка

| Строка | Смысл |
| --- | --- |
| `ПЕРЕЗАРЯДКА` | заголовок |
| `6.0 с` / `ГОТОВ` / `5.6 с ПАУЗА` / `НЕТ ДАННЫХ` | остаток и состояние; зелёный на `ГОТОВ`, янтарный на паузе |
| `[###.....] 37 % · цикл 9.4 с` | доля пройденного цикла и полная длительность цикла |
| `СНАРЯД №2 · запас —` | текущий снаряд и его остаток |
| `прочие: №0 11 · №1 7` | остаток по остальным наблюдавшимся типам снарядов |
| `интерполяция · событие 3 с назад` | откуда взято число на второй строке |

Последняя строка — не украшение. Она различает четыре разных утверждения:

- `интерполяция · событие N с назад` — число рассчитано из события перезарядки
  и времени, прошедшего с него;
- `значение из события` — клиент сам сообщил, что перезарядка завершена;
- `готовность рассчитана` — отсчёт дошёл до нуля, но события о завершении не
  приходило. Это вывод, а не наблюдение, и строка об этом говорит;
- `пауза` — клиент сообщил `paused`, отсчёт заморожен;
- `нет часов кадра` — событие пришло без пригодной отметки времени, поэтому
  показано ровно то, что наблюдалось, без пересчёта;
- `перезарядка не наблюдалась` — событий перезарядки в этом бою ещё не было.

## Плавный отсчёт без работы каждый кадр

Клиент публикует `wotbmod.gameplay.reload_state_changed` из
`ReloadTimer::setState`, то есть на переходах, а не каждый кадр. В payload есть
`duration_seconds`, `progress` и `remaining_seconds`. `wotb.battle` запоминает
рядом с каждым полем `timestamp_ns` события, из которого оно пришло, поэтому на
экране всегда

```text
остаток на момент события  -  (сейчас  -  отметка времени этого события)
```

«Сейчас» — это отметка времени последнего `wotbmod.frame.update`, полученная
через `wotb.timer.now_ms()`. Обе отметки ставит один и тот же steady-часовой
источник (`src/v3/runtime_services.cpp`, `NowNs()`), поэтому вычитание имеет
смысл. Аргумент `delta_seconds` функции `on_frame` намеренно не используется:
это длительность, а не часы, и вычесть её из отметки события нельзя.

Между событиями клиент не опрашивается вообще.

Перерисовка — 10 раз в секунду. Десятая секунды — самый мелкий шаг, который
панель показывает, поэтому более частая перерисовка не может изменить ни одного
символа; а изменение текста здесь не бесплатно — loader помечает контрол
`rebuild_pending` (`loader/v3_native_client_services.cpp`,
`QueueUpdatedUiRebuild`), и backing DAVA-ресурс после этого перестраивается.

Строка не перерисовывается, если её текст не изменился, причём сравнение идёт
раньше `string.format`: сначала сравниваются десятые доли секунды и целый
процент, и только при их изменении собирается строка.

## Цена по кадрам

Измерено, а не оценено: 600 кадров на случай, с остановленным сборщиком, с
вычитанием того же прогона при пустом `on_frame`.

| Состояние | Мусор | `control_set_text` |
| --- | ---: | ---: |
| ангар, каталог модов, ввод текста | ~0 | 0 |
| бой, событий перезарядки ещё не было | ~2.4 КБ / 100 мс | 0 |
| бой, `ГОТОВ`, ничего не меняется | ~2.4 КБ / 100 мс | 0 |
| бой, идёт отсчёт | ~2.5 КБ / 100 мс | 13.6 в секунду |

Около 2.4 КБ из 2.5 — это `wotb.battle.snapshot()`, который на каждый вызов
пересобирает таблицы `values`, `source`, `updated_ns` и `unavailable`.
Собственное форматирование мода — оставшиеся ~0.1 КБ.

`control_set_text` доходит до клиента не более 20 раз в секунду во время
отсчёта: строка остатка на частоте тика и строка доли при изменении целого
процента. В покое — ноль.

Вне боя мод не стоит клиенту ничего: таймер перерисовки снимается, а последний
снятый таймер уносит с собой подписку `wotb.timer` на `wotbmod.frame.update`,
поэтому диспетчер событий на этот мод по этой теме даже не смотрит.

## Чего этот API сейчас не даёт

**Запас снарядов.** На этой сборке клиента (11.19.0.834 x86) событие
`wotbmod.gameplay.ammo_changed` всегда несёт `count = -1`
(`loader/wotb_mod_loader.cpp`, `AmmoChangedDetour`). Минус единица — это
признак «неизвестно», а не количество, поэтому мод не наблюдал ни одного
остатка и пишет прочерк, а строкой ниже объясняет, почему. Само событие при
этом полезно: оно достоверно сообщает, какой снаряд выбран сейчас и какой был
выбран до этого. Как только сборка начнёт публиковать настоящий `count`, те же
строки заполнятся сами — код менять не придётся.

**Числовое состояние перезарядки.** `WotbModV3ReloadEventData.state` — целое,
прочитанное из объекта клиента, и ни одной константы для его значений
заголовки не публикуют. Мод не выдумывает им названий и вообще их не
показывает: `ГОТОВ` и отсчёт выводятся из `remaining_seconds`, `paused` и
длительности, то есть из полей, смысл которых определён.

## Разрешения

| Разрешение | Зачем |
| --- | --- |
| `core` | `wotb.log` (через `wotb.core.log`), `wotb.context.current()` (через `wotb.core.get_context`) и `wotb.handles.release` для handle активного экрана |
| `events.public` | подписки `wotb.battle` на `reload`, `ammo` и `lifecycle`, подписка `wotb.timer` на кадр, подписка `wotb.panel` на смену экрана |
| `ui.create` | создание собственных контролов панели |
| `ui.modify.own` | изменение текста, видимости и цвета собственных контролов |
| `ui.modify.game` | привязка корня панели к активному экрану клиента |
| `battle.ui` | панель существует в бою |

Четыре UI-разрешения запрашиваются вместе не «на всякий случай»: hand-written
семейство `wotb.ui` требует весь набор целиком для любого своего слота
(`loader/lua/lua_bind_ui.cpp`, `kUiPermissions`), поэтому это и есть минимум для
мода, который вообще что-то рисует.

Не запрашиваются `storage` и `settings`: настроек мод не хранит. Геометрия и
частота перерисовки заданы константами в начале `main.lua` — `PANEL_WIDTH`,
`PANEL_HEIGHT`, `PANEL_ANCHOR`, `PANEL_MARGIN` и `REDRAW_MS`. Не запрашиваются
`entity.public.visible` и `game.entity.public`: `wotb.players` мод не читает.

## Видимость и уборка

Панель существует только в `BATTLE`, `TRAINING` и `REPLAY` и полностью
размонтируется при `MOD_SCREEN` и `TEXT_INPUT` — это маска по умолчанию
`wotb.panel`, собранная из `wotb.context` по именам. Каталог модов панель не
перекрывает и ввод поверх него не перехватывает.

`on_disable` не оставляет ни одного контрола, ни одной подписки и ни одного
таймера: панель размонтируется, `wotb.battle.stop()` снимает свои подписки,
таймер перерисовки снимается по своему id, а вместе с ним уходит и подписка на
кадр.

Все вызовы API читают второе возвращаемое значение. Ошибка, которую некому
вернуть, считается и пишется в лог один раз на текст: клиент, который отказывает
в одном и том же вызове каждый тик, стоит одной строки лога, а не десяти в
секунду.

## Как это проверялось

Клиент не запускался. `main.lua` прогонялся на собранном из
`mod_api/third_party/lua` интерпретаторе Lua 5.4 против **настоящих**
convenience-модулей: `wotb.log`, `wotb.timer`, `wotb.battle`, `wotb.context`,
`wotb.panel` и `wotb.available` извлекались из
`loader/lua/lua_preludes.cpp` и `loader/lua/lua_bindings.cpp` как есть.
Мокировался только C-уровень — `wotb.core`, `wotb.events`, `wotb.ui`,
`wotb.handles`.

92 проверки: интерполяция против часов, монотонность отсчёта, повторная
привязка при новом событии, пауза, событие без отметки времени, недоступный
снимок боя, отказ клиента в `get_active_screen`, отсутствие интерфейса `ui`
вовсе, полная уборка на `on_disable` и на повторном `on_enable`, баланс
созданных и уничтоженных контролов, баланс выданных и возвращённых handle
экрана, а также статическая проверка, что мод не называет ни одного имени вне
sandbox-а (`io`, `os`, `package`, `debug`, `coroutine`, `utf8`, `require`,
`dofile`, `loadfile`, `collectgarbage`, глобальный `warn`).

## Установка

Скопируйте каталог как:

```text
mods\lua\example.lua_reload_timer
```

Убедитесь, что в `mods\mods.ini` включён `wotbmod.lua_host`. Lua host сам
обнаруживает каталоги внутри `mods\lua`; отдельная строка для этого мода не
нужна.
