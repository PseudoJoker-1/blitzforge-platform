# blitzforge.catalog — каталог модов в ангаре

Иконка в левой колонке ангара открывает штатный экран каталога с двумя
вкладками. Экран — родной UI клиента: его вклеивает в `Hangar.yaml`
ресурсный пакет `blitzforge.catalog.ui` (`examples/catalog_ui`), а этот
Lua-мод им управляет.

- **Каталог** — то, что опубликовано на https://blitz-forge.org
  (`index.json` через `wotb.http`), с состоянием на этой машине: не
  установлен / установлен / доступно обновление / не для этого клиента.
  Кнопка карточки: УСТАНОВИТЬ, ОБНОВИТЬ или УДАЛИТЬ (с подтверждением).
- **Кастомные моды** — всё, что стоит мимо портала: пакеты из файла или по
  `wotbmod://` с другого каталога, папки в `mods\lua`, архивы в `mods\`.
  Кнопка карточки: ВЫКЛЮЧИТЬ / ВКЛЮЧИТЬ (`[mods] <id>=0|1` в `mods.ini`),
  для ресурсных пакетов — УДАЛИТЬ. Системные пакеты (`wotbmod.lua_host`,
  сам каталог и его экран) помечены СИСТЕМНЫЙ и не трогаются.

Каждое действие — команда `wotbmod.exe` (`launcher open wotbmod://…`,
`uninstall`, `enable`, `disable`), запущенная скрытым процессом через
`wotb.packages`; экран показывает код выхода и последнюю строку в строке
статуса. После успеха появляется полоса ПЕРЕЗАПУСТИТЬ КЛИЕНТ
(`wotbmod restart-client`): установленные Lua-папки хост читает один раз при
старте, а ресурсные пакеты меняют файлы. Без сети показывается последняя
сохранённая копия каталога (`wotb.store`, ключ `catalog.index`).

## Как это устроено

На 11.20 текст штатных контролов из мода не меняется, а клики по штатным
кнопкам не приходят как `EVENT_CLICK`. Поэтому:

- все подписи экрана — литералы в YAML («лица» кнопок УСТАНОВИТЬ / ОБНОВИТЬ /
  УДАЛИТЬ / ВЫКЛЮЧИТЬ / ВКЛЮЧИТЬ / СИСТЕМНЫЙ / НЕ ДЛЯ 11.20 у каждой из
  восьми карточек), мод только показывает нужное `wotb.screen.set_visible`;
- имена, версии, статус и номер страницы — свои текстовые контролы
  (`wotb.ui.create`, `CONTROL_TEXT`, шрифт клиента) поверх штатных рамок;
- клики — `wotbmod.ui.input` (`action == 3`) и сверка с прямоугольниками,
  собранными по `control_get_parent` (как в `cluster_picker`); лица карточки
  берутся из её детей (`wotb.screen.children` + `info().id`);
- бит контекста `MOD_SCREEN` поднимается через флаг ввода контрола
  `ModCatalogStateMarker` (`control_set_interactable`), пока экран открыт —
  панели других модов на это время прячутся;
- при смене экрана все handle забываются и находятся заново по первому
  отпусканию указателя.

## Права

`core`, `events.public`, `storage`, вся UI-семья (`ui`, `ui.create`,
`ui.modify.own`, `ui.modify.game`, `battle.ui`), `network.http` и
`packages.manage` (REVIEWED: мод управляет тем, что клиент запускает).
`network.http`, а не `network:https://blitz-forge.org`: на Lua-хосте таблица
`wotb.http` открывается только правом `network.http` (см. «Известные
ограничения»); мод ходит только на `blitz-forge.org`, URL зашит в `main.lua`.

## Разработка

```
python tools\wotbmod.py scan examples\catalog
xcopy /E /I examples\catalog "<игра>\mods\lua\blitzforge.catalog"
```

Экран нужен установленный: `wotbmod install <blitzforge.catalog.ui-…wotbmod>`
(см. `examples/catalog_ui/README_RU.md`). Логи: `<игра>\wotb_mod_loader.log`,
категория `[v3:catalog]`; `[loader] V3 UI context=66 … catalog=yes` — экран
открыт.
